# 创建页 UI 重构设计

## 背景

当前 `创建页` 已具备完整流程，包括照片上传、基础信息填写、藏品类型选择和底部提交操作，但页面存在以下问题：

- 组件体积偏大，首屏信息密度高，单手操作时节奏偏重
- 上传区、表单区、类型区、提示区的视觉重量接近，主次不够清晰
- 输入、切换、校验虽然完整，但整体更像展示型页面，不够像高频操作的移动端创作工具
- 页面风格有氛围感，但不够轻盈精致，影响“好看”和“好交互”的统一

本次目标是在保留项目主题气质的前提下，对 `创建页` 做一次偏产品化、轻量化、精致化的重构。

## 目标

- 把 `创建页` 重构为更轻量、更精致的移动端创作入口
- 明确页面主次，让用户在 3 秒内知道先做什么、下一步做什么
- 缩小核心组件体积，降低滚动压力，提升单手操作体验
- 保留当前项目的“显影 / 遗址 / 藏品”语义，但弱化厚重展示感
- 不改变核心业务流程，仍维持“上传 -> 填写 -> 选择类型 -> 生成”的主链路

## 非目标

- 不修改生成页、结果页、分享页的信息结构
- 不新增真实相册、相机、上传接口或后端联调逻辑
- 不扩展新的业务字段或新的藏品类型
- 不引入全新设计系统或替换现有主题色体系

## 设计方向

采用 `轻量精致型` 方案，并允许对当前 `创建页` 完全重构，不受现有视觉结构限制。

方向定义如下：

- 页面更像成熟的移动端创作工具，而不是一组概念展示卡片
- 视觉语言保留温暖深色背景和类型主题色，但减少厚重描边、过高卡片和冗长文案
- 重点优化“组件过大、不好交互”的问题，让点击区域更明确、信息块更紧凑、操作路径更短

## 信息架构

新的 `创建页` 采用 3 层结构：

1. 顶部轻头部
2. 中部主创作区
3. 底部固定操作区

### 顶部轻头部

头部只承担页面定位，不承担复杂说明。

- 标题建议改为 `创建藏品` 或 `开始创作`
- 副标题压缩为一行，说明“上传照片并补全信息，即可开始生成”
- 保留轻量的主题色点缀，但不再使用高占比说明区

### 中部主创作区

按优先级重排为：

1. 照片上传卡
2. 基础信息输入组
3. 藏品类型选择器
4. 当前类型说明

设计原则：

- 第一视觉焦点必须是照片上传
- 信息填写与风格选择属于次级任务，不抢首屏核心焦点
- 类型说明降级为动态说明区，而不是一整张独立提示卡

### 底部固定操作区

底部固定区保留，但尽量简洁：

- 一行状态文本
- 一个主操作按钮

不再承载大段解释性文案，避免与主内容区域竞争注意力。

## 页面布局

### 1. 头部

现状问题：

- 头部文字量偏多，首屏有效操作区域被压缩

重构方案：

- 标题与副标题压缩为紧凑头部
- 减少顶部空白和段落感
- 让上传卡尽早进入首屏

预期结果：

- 用户进入页面后，不需要先读大段文字
- 页面第一眼即进入“可操作状态”

### 2. 上传卡

现状问题：

- 上传区域高度偏大，默认态和已上传态都较厚重
- 状态标签、文案、按钮层层叠加，视觉负担较重

重构方案：

- 上传卡作为页面主视觉，但整体高度缩短
- 推荐使用更轻的图片比例，如 `16:10` 或 `4:3`
- 默认态仅保留：
  - 一个简短标题
  - 一行辅助文案
  - 一个清晰的主上传入口
- 已上传态下：
  - 图片作为主视觉
  - `替换照片` / `移除` 改为贴近图片的小号胶囊按钮
  - 状态角标缩小并吸附在图片上方或角落，不再独占一整行

预期结果：

- 首屏更轻，上传动作更直接
- 图片上传后的页面不会瞬间变成“大块头”

### 3. 基础信息输入组

现状问题：

- 当前 `MetadataForm` 视觉上更像一张展示型卡片
- 输入框高度和区块感较强，不够适合连续输入

重构方案：

- 保留一个承载表单的轻卡，但缩小内边距与字段间距
- 输入区改成更偏移动端原生表单的样式
- 三个字段仍保留：
  - `作品标题`
  - `遗址名称`
  - `地点`
- 字段层级调整：
  - `作品标题` 作为主输入，视觉上略更突出
  - `遗址名称`、`地点` 为次级输入
- 标签弱化为小字标题
- 错误提示贴近字段，不独立占大块空间

预期结果：

- 输入更顺手，键盘弹起后的操作阻力更小
- 页面从“厚卡片堆叠”转向“轻量表单流”

### 4. 类型选择器

现状问题：

- 当前 `TypeSelector` 单卡信息过满，卡片面积偏大
- 三种类型同时展开时，页面重心被大卡片拉散

重构方案：

- 改为横向滑动小卡片，优先适配移动端手势
- 每张卡片只保留：
  - A / B / C 标识
  - 类型名称
  - 一句短描述
- 不在卡片内部承载过多说明性内容
- 选中态通过以下方式体现：
  - 主题色边框
  - 轻量底色抬升
  - 低强度光晕
- 类型详细说明移出卡片，在下方展示为单独一段动态文本

预期结果：

- 类型选择更轻、更快
- 页面整体不会因为 3 张大卡而显得臃肿

### 5. 动态说明区

现状问题：

- 当前“显影提示”是一整张卡，和前面的上传、表单、类型区争夺层级

重构方案：

- 取消独立的大提示卡
- 改为紧贴类型选择器下方的一段动态说明文字
- 仅展示当前选中类型对应的简洁说明
- 当表单未完成时，可在同一区域补充一条极短的状态提示

预期结果：

- 提示信息存在，但不抢视觉中心
- 整个页面更清爽

### 6. 底部固定操作区

现状问题：

- 底部说明文本偏长，容易稀释按钮主次

重构方案：

- 固定底部保留一条状态文本和一个主按钮
- 主按钮文案统一为 `开始生成`
- 状态文本仅用于提示：
  - 未完成时还缺哪些关键项
  - 完成时已准备就绪
- 不再频繁切换超长按钮文案

预期结果：

- 页面始终存在稳定主操作锚点
- 用户不需要重新理解按钮含义

## 交互规则

### 首屏交互节奏

- 进入页面后默认焦点落在上传卡
- 首次任务是上传，不让表单或类型卡抢占首屏心智

### 输入反馈

- 不采用“直到提交才统一报错”的单一策略
- 用户输入后即可进入已填写状态
- 字段失焦后进行单字段校验
- 点击主按钮时，再汇总提示未完成项

这样可以避免两个问题：

- 未输入时满屏错误，打断体验
- 到最后一步才暴露问题，形成挫败感

### 类型切换

- 切换时保留当前输入和照片状态，不清空表单
- 卡片点击反馈采用轻量按压，不做大幅跳动
- 下方说明文字使用淡入替换，避免突兀闪烁

### 提交逻辑

- 主按钮固定位置不变
- 未完成时允许点击，用于明确告知缺失项
- 已完成时高亮可用，但不使用强烈炫光

### 键盘与滚动

- 键盘弹起时，当前输入框不能被底部固定区遮挡
- 页面重构后应减少超长滚动
- 类型选择器应在键盘弹起和收起后都能快速触达

## 动效原则

- 所有交互以“轻、短、稳”为原则
- 点击反馈以 100ms - 160ms 的按压回弹为主
- 动效只服务于状态确认，不制造表演感
- 保留类型主题色，但限制 glow 面积和强度

## 建议实现策略

### `create.tsx`

- 重组页面顺序与块级层次
- 去掉当前独立的大提示卡
- 将类型说明收拢为轻量动态说明区
- 简化底部状态文案和主按钮文案

### `upload-dropzone.tsx`

- 降低默认态与预览态整体高度
- 减少默认文案层数
- 把替换 / 删除操作做成更紧凑的小按钮
- 缩小状态标签的占位方式

### `metadata-form.tsx`

- 缩小卡片内边距、字段间距、输入框高度
- 强化主字段与次级字段层次
- 让错误提示更靠近字段，而不是形成视觉噪音

### `type-selector.tsx`

- 从当前偏高信息密度卡片，改成移动端优先的轻量横滑卡
- 卡片内容收敛为“标识 + 名称 + 单句说明”
- 详细说明移动到列表之外

## 风险与约束

- 页面会比现状更轻，若过度简化，可能削弱部分“显影仪式感”
- 若 `ScreenShell` 的外围留白和装饰层级不调整，创建页即使组件缩小，也可能仍显偏重
- 若底部固定区与键盘处理不当，会影响表单输入体验

因此实现时应优先验证：

- 首屏是否更轻
- 上传后是否仍保持整洁
- 键盘弹起时是否依然顺手

## 验收标准

- 用户进入页面后，首屏优先感知上传动作
- 页面整体高度感明显收敛，不再由大卡片主导
- 表单输入体验更像移动端原生产品，而不是展示块堆叠
- 类型选择器更轻量，切换时不影响页面节奏
- 底部主按钮始终清晰可达，状态反馈简短明确
- 整体视觉气质从“厚重概念页”转为“轻量精致创作页”

## 测试与验证

- 手动检查首屏可见内容是否聚焦
- 手动检查上传前、上传后两种状态的高度变化是否合理
- 手动检查键盘弹起后的输入可达性
- 手动检查三种类型切换时的状态保持和文案切换
- 手动检查提交时的缺项提示是否准确、克制

## 结论

本次重构不是对现有创建页做局部修饰，而是以“轻量精致、移动端优先、组件更小更顺手”为目标，对页面进行结构级重排和组件级减重。

最终结果应当让 `创建页` 既保留项目调性，又具备成熟移动产品的清晰度、节奏感和可操作性。
