# 分享页微信发布工作台设计

## 背景

当前 `分享页` 已具备基础能力，包括海报预览、分享文案展示和底部 mock 操作区，但整体仍更像一个“分享模板展示页”，而不是一个真正服务于发布动作的移动端分享工作台。

现状问题主要集中在以下几类：

- 海报预览占比过高，页面主角仍是展示，而不是发布前整理
- 文案区只是静态展示，不支持用户在发出前做最后一次整理
- 操作区仍是通用动作列表，缺少明确的提交优先级
- 页面与 `结果页` 的承接不够强，用户从查看作品跳到分享页后，缺少“准备发布”的明确心智切换
- 微信生态下高频的“复制文案 + 保存图片 + 去分享”链路没有被强调

本次重构目标是在保留现有藏品主题气质的前提下，把 `分享页` 从模板展示页重构为一个面向微信生态的轻量发布工作台。

## 目标

- 把 `分享页` 重构为偏微信生态的 `发布前整理页`
- 让用户进入页面后，优先感知“编辑和提交内容”，而不是单纯看海报
- 支持在页面内对标题、正文、标签和朋友圈短句进行轻编辑
- 明确主次操作顺序，形成 `去分享 -> 复制文案 -> 保存图片 -> 返回作品` 的动作链路
- 让 `结果页 -> 分享页` 的跳转更像进入发布准备阶段，而不是进入一个静态模板页

## 非目标

- 不接入真实微信 SDK、朋友圈 API 或公众号发布 API
- 不新增后端发布记录、草稿同步或跨端分享状态同步
- 不改动 `结果页` 的整体信息结构，只调整它到分享页的语义承接
- 不把分享页扩展成多步骤流程页，仍保持单页工作台模式

## 设计方向

本次设计采用 `A. 微信发布工作台` 方案。

方向定义如下：

- 页面定位从“海报展示”切换为“发布前整理”
- 海报仍保留，但降级为辅助预览，不再占据整页主视区
- 页面核心变为可编辑的分享内容面板
- 交互重点是帮助用户更快完成图文整理，然后去微信生态发布

## 页面定位

新的 `分享页` 应承担以下职责：

1. 承接 `结果页` 的成品内容
2. 让用户在发出前完成最后一轮内容确认
3. 提供微信导向的轻编辑与操作入口
4. 帮助用户以更低阻力完成“复制文案 / 保存图片 / 去分享”

用户进入页面后的心智应当从“这是我的作品”切换为“我现在准备把它发出去”。

## 信息架构

新的 `分享页` 采用 5 段式结构：

1. 顶部页头
2. 海报辅助预览区
3. 分享编辑区
4. 微信场景提示区
5. 底部发布操作区

### 1. 顶部页头

页头只负责建立页面任务，不承担大段说明。

- 标题建议改为 `整理分享内容` 或 `发布前确认`
- 副标题强调“适合微信生态分享前快速整理”
- 头部密度应比当前结果页和展示页更轻，尽早让用户进入编辑区

### 2. 海报辅助预览区

海报预览保留，但需要明显收缩体量，不再占据整个首屏。

- 使用一张紧凑版预览卡
- 预览图仍基于当前 `SharePosterPreview` 的图像能力
- 增加 2 至 3 个轻提示，例如：
  - `已生成分享图`
  - `适合朋友圈封面`
  - `可保存后直接发送`

设计原则：

- 可见，但不抢戏
- 让用户知道“图已经准备好了”
- 不让海报重新成为页面主角

### 3. 分享编辑区

这是整个页面的核心区域。

页面需要支持以下 4 类内容编辑：

1. `朋友圈短句`
2. `分享标题`
3. `分享正文`
4. `推荐标签`

结构顺序遵循微信内容消费习惯：

- 先看短句
- 再看标题
- 再看正文
- 最后看标签

编辑区需要满足以下要求：

- 进入页面后直接可编辑，不要求先点击“编辑”按钮
- 每个字段独立可修改
- 默认带入当前作品已有的 `share` 数据
- 字段样式更像发布面板，不像只读说明卡

### 4. 微信场景提示区

页面需要提供轻量场景引导，但不做复杂渠道切换。

建议以一个轻卡或简洁说明块呈现以下场景：

- `适合发朋友圈`
- `适合发群分享`
- `适合复制到公众号草稿`

目的不是新增渠道逻辑，而是帮助用户快速判断这些内容怎么用。

### 5. 底部发布操作区

底部区应为页面最明确的动作锚点，且主次顺序必须清楚。

按钮优先级定义如下：

1. 主按钮：`去分享`
2. 次按钮：`复制文案`
3. 次按钮：`保存图片`
4. 弱按钮：`返回作品`

设计原则：

- 主按钮承担“整理完就去发”
- `复制文案` 优先级高于 `保存图片`
- `返回作品` 必须保留，但不应与前 3 个动作争抢注意力

## 页面布局

### 1. 顶部区

建议页面头部文案：

- 标题：`整理分享内容`
- 副标题：`编辑图文后，可直接用于微信生态分享`

视觉要求：

- 比当前分享页更轻
- 不延续“模板展示页”的语气
- 强调用户当前处于“准备发布”阶段

### 2. 预览区

预览区应放在编辑区之前，但只占据有限高度。

建议内容包括：

- 一张缩略版海报预览卡
- 一行辅助状态标签
- 不再放大段介绍性文案

### 3. 编辑区

编辑区按以下顺序展开：

1. `朋友圈短句`
2. `分享标题`
3. `分享正文`
4. `推荐标签`

字段策略如下：

#### 朋友圈短句

- 一句话
- 适合作为朋友圈首行或分享引导语
- 来源可基于当前 `callToAction` 提炼

#### 分享标题

- 比海报标题更口语化、更适合转发
- 不能只是简单复用海报标题
- 应保留作品主题，但弱化展陈语气

#### 分享正文

- 基于当前 `caption` 做可复制的正文表达
- 保留文化内容与作品语义
- 句式更偏真实分享文本，而不是纯展示说明

#### 推荐标签

- 默认控制在 3 个左右
- 展示精选标签，而不是把所有 hashtag 全部铺开
- 允许调整或删除，不强调数量

### 4. 场景提示区

场景提示区应放在编辑区之后、底部操作区之前。

建议使用轻量形式呈现：

- `发朋友圈：建议使用短句 + 海报图`
- `发群分享：建议复制正文后补一句个人感受`
- `公众号草稿：建议保留标题和正文主体`

该区域的作用是帮助用户理解内容用途，不承担业务逻辑。

### 5. 底部操作区

底部固定区承载 4 个操作：

- `去分享`
- `复制文案`
- `保存图片`
- `返回作品`

操作区文案和布局应满足：

- 主操作最强
- 次操作之间层级清晰
- 弱操作明确可见但不突出

## 交互规则

### 默认状态

- 页面加载后自动带入当前作品已有 `share` 数据
- 用户进入页面即可修改内容
- 不需要额外触发编辑模式

### 编辑状态

- 每个字段允许单独修改
- 修改后页面即时反映最新内容
- 预览图不需要在本次重构中做到实时重新排版导出，只要保留作为辅助预览即可

### 提交反馈状态

动作触发后采用轻反馈，而不是占用大面积卡片：

- 复制文案后：显示 `朋友圈文案已复制`
- 保存图片后：显示 `分享图已保存`
- 去分享后：显示 `已唤起分享动作` 或当前 mock 提示

当前页面中的长 `feedback` 文本不再保留为主内容的一部分，应降级为轻量状态反馈。

### 回退状态

- `返回作品` 作为弱操作保留
- 从视觉上弱于 `复制文案` 和 `去分享`
- 仍需确保用户能快速回到 `结果页`

## 文案策略

### 页面语气

- 从“模板展示”转向“发布整理”
- 更产品化、更直接
- 保留项目调性，但减少概念展示腔调

### 字段语气

- `朋友圈短句`：短、轻、可立即发送
- `分享标题`：口语化、利于转发
- `分享正文`：完整但不冗长
- `推荐标签`：精选、不堆叠

## 错误与空状态

### 无效作品

如果 `id` 无效或未找到作品：

- 沿用结果页相似的清晰回退方式
- 提供 `返回作品列表` 或 `返回创作页` 的明确入口

### 分享内容为空

如果某个字段缺失：

- 使用当前作品的默认生成文案兜底
- 不允许出现关键字段留空后直接展示空白区域

### 真实能力未接入

在真实分享、保存、复制能力未接入前：

- 保留 mock 行为
- 但反馈应以轻量状态提示表达
- 不再单独占用一个大卡片来显示反馈说明

## 建议实现策略

### 1. 先改页面骨架

- 在 `share/[id].tsx` 中重排信息结构
- 把页面从“预览 + 文案卡 + ActionSheet”改成“预览 + 编辑 + 场景提示 + 操作面板”

### 2. 再缩小预览组件

- 改造 `SharePosterPreview`
- 降低高度和视觉重量
- 保留主题色与基础氛围

### 3. 新增编辑与操作组件

- 分别实现编辑卡、场景提示卡、操作面板
- 保持单一职责，避免分享页主文件过重

### 4. 最后接回结果页语义

- 确保 `结果页 -> 分享页` 的入口文案和动作语义一致
- 让“分享藏品”更像“去整理分享内容”

## 风险与约束

- 若编辑区做得过重，页面可能反而变成表单页，削弱分享氛围
- 若预览区缩得过小，用户会失去对最终发出内容的直觉把握
- 若底部操作层级不清楚，页面会退化成多个同权按钮堆叠
- 若字段默认文案不够贴近微信语境，重构后的工作台会显得形式正确但不够好用

因此实现时应优先验证：

- 用户是否能一眼明白这是“发布前整理页”
- 首屏是否仍保留足够的作品感
- 主次操作是否足够清楚
- 默认文案是否像真的会被复制出去

## 验收标准

- 用户进入分享页后，第一感知是“整理并发出内容”
- 海报预览明显存在，但不再压过编辑区
- 页面支持对短句、标题、正文、标签进行轻编辑
- 主按钮 `去分享` 的优先级最强
- `复制文案` 的重要性明确高于 `保存图片`
- 当前大块反馈卡被移除，动作反馈改为轻提示
- 页面整体更像移动端发布工作台，而不是展示模板

## 测试与验证

- 手动检查 `结果页 -> 分享页` 跳转是否正常
- 手动检查初始字段值是否正确带入
- 手动检查编辑后内容是否即时更新
- 手动检查底部操作层级是否清晰
- 手动检查无效 `id` 和空字段兜底
- 手动检查 mock 操作是否仍有明确反馈

## 结论

本次重构不是给当前 `分享页` 做局部美化，而是把它从一个展示模板页重构为一个更接近真实产品使用场景的微信发布工作台。

最终结果应当让用户在保留作品氛围感的同时，更顺畅地完成图文整理、图片保存和微信分享准备。
